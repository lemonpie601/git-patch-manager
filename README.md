# 패치 관리자 · Marinara Engine

마리나라 엔진의 **서버 패치**를 관리하는 개인 확장입니다.

마리나라의 패치는 두 가지 방식이 있고, 이 확장은 둘 다 관리합니다.

| 방식 | 생김새 | 어떻게 들어가나 | 켜고 끄기 |
| --- | --- | --- | --- |
| **런타임 패치** | `*-runtime.cjs` 같은 파일 하나(설정 JSON이 곁에 있기도 함) | `.env`의 `NODE_OPTIONS=--require=…`로 마리나라가 켜질 때 불러와, **파일은 그대로 두고** 불러오는 코드만 메모리에서 고침 | `NODE_OPTIONS`에 넣고 빼기 · 순서 바꾸기 → 재시작 |
| **파일 패치** | `patch/apply-patch.mjs` 같은 Node 스크립트 | 마리나라가 꺼진 동안 실행해 패키지 파일(`server.mjs` 등)을 직접 고침, `/*이름:start*/` 같은 표식과 `.gmm-backup` 백업을 남김 | 스크립트 실행 / `--restore` |

JSON 파일(예: `gf-customizer-edits.json`)은 패치 자체가 아니라 런타임 패치가 읽는 **설정·레시피**입니다.

이 확장은 패치를 모아 정리하고, 이미 깔린 패치를 찾아 반영하고, 업데이트를 확인하고, 적용·되돌리기·켜기/끄기·검사·백업본 정리까지 합니다.

GitHub 확장 관리자의 화면 구성(검색·그룹·태그·메모·즐겨찾기·카드/목록 보기)을 그대로 응용했습니다.

| 기능 | 설명 |
| --- | --- |
| 패치 모으기 | 공개 GitHub 저장소, 파일, **이미 받아 둔 폴더**에서 패치 스크립트를 찾아 추가 |
| 업데이트 확인 | GitHub에 연결한 패치의 새 코드 확인 · 코드 보고 받기 |
| 적용 상태 | 마리나라 설치 기록의 해시로 "적용됨 / 다시 실행 필요 / 미적용"을 자동 표시 (대상 패키지가 업데이트되어 패치가 사라지면 알려 줌) |
| 자동 적용 | 서버에 도우미를 한 번 깔면, 버튼 하나로 마리나라를 재시작하면서 꺼진 틈에 패치 |
| 실행 파일 | 도우미 없이 직접 돌리는 `marinara-patches.mjs` (적용 · 되돌리기) |
| 설치된 패치 찾기 | 도우미가 `.env`의 `NODE_OPTIONS`(런타임 패치)와 애드온 폴더의 패치 스크립트, 패키지 속 표식을 읽어 **관리자 목록에 자동으로 넣음** |
| 런타임 패치 | 켜기·끄기·불러오는 순서 바꾸기, 맞춘 패키지 버전과 지금 버전이 다르면 "버전 다름" 경고, 읽는 설정 JSON 표시 |
| 백업본 정리 | `*.gmm-backup`, `.env.before-…`, 애드온 폴더의 `.bak`·`.before-…`·옛 버전 사본, `.prev`·`.backup-…` 폴더를 찾아 지움 |

## 왜 이렇게 동작하나요?

- **패치는 마리나라가 꺼져 있을 때만 넣을 수 있습니다.** 켜진 채로 넣으면 마리나라가 설치 기록(`installed.json`)을 옛 해시로 덮어써서, 다음에 켤 때 무결성 검사에 걸립니다.
- **브라우저 확장은 서버 파일을 고칠 수 없습니다.** 마리나라의 서버 확장도 파일 접근이 막힌 샌드박스에서 돌아갑니다.

그래서 실제 적용은 서버 컴퓨터에서 Node로 합니다. 방법은 두 가지입니다.

1. **도우미(`marinara-patch-helper.mjs`)** — 권장. 한 번 깔아 두면 그다음부터는 버튼만 누르면 됩니다.
2. **실행 파일(`marinara-patches.mjs`)** — 매번 받아서 터미널에서 실행합니다.

> 설정 → 고급의 "서버 재시작"만으로는 패치할 수 없습니다. 재시작은 끄자마자 바로 다시 켜서 패치할 틈이 없습니다. 도우미는 마리나라의 재시작 관리자 역할을 대신 맡아서, 그 틈을 만들어 패치합니다.

## 확장 설치 (공통)

1. 이 저장소를 내려받거나(Code → Download ZIP) 아래 세 파일을 받습니다.
   - `manifest.json`, `extension.js`, `extension.css`
2. 마리나라 **설정 → 외부 확장**에서 **확장 폴더 가져오기**로 그 폴더를 고릅니다. GitHub 확장 관리자가 있다면 이 저장소 주소로 설치해도 됩니다.
3. 확장을 켭니다(검토 후 켜기).
4. 외부 확장 화면 위쪽에 생긴 **[패치]** 버튼으로 엽니다.

## 🖥️ 로컬 기준 — 마리나라를 내 컴퓨터에서 돌릴 때

브라우저와 마리나라가 **같은 컴퓨터**에 있는 경우입니다.

### 1. 패치 추가

**[패치 추가]**에서 고릅니다.

- **폴더에서** — 이미 받아 둔 패치가 있으면 그 폴더를 고릅니다(예: `Downloads\미니겜`). 안에 있는 `patch/` 스크립트를 모두 찾아 한 번에 추가합니다.
- **파일에서** — `apply-patch.mjs` 같은 파일을 직접 고릅니다. 여러 개 골라도 됩니다.
- **GitHub 저장소** — `https://github.com/소유자/저장소`를 넣으면 패치 스크립트를 찾습니다. 파일 주소(`…/blob/main/patch/apply-patch.mjs`)를 넣어도 됩니다.

예전에 이미 적용해 둔 패치라면, 추가한 뒤 **[검사]**에서 **이 컴퓨터에서 폴더 고르기** → 마리나라 엔진 폴더(또는 `packages\server\data`)를 고르세요. 패키지 속 패치를 찾아 "적용됨"으로 표시합니다.

### 2-A. 자동 적용 (도우미, 권장)

처음 한 번만 설정합니다.

1. **[실행] → 자동 적용 → `marinara-patch-helper.mjs` 받기**
2. 받은 파일을 **마리나라 엔진 폴더**(`packages` 폴더가 있는 곳)에 넣습니다.
3. 마리나라를 평소처럼 런처나 `start.bat`으로 켜지 말고, 엔진 폴더에서 터미널을 열어 아래처럼 켭니다.
   ```bash
   node marinara-patch-helper.mjs
   ```
   처음 켜면 이렇게 **연결 코드**가 나옵니다.
   ```
   [패치 도우미] 연결 코드: 1a2b-3c4d-…  ← 패치 관리자 → 실행 → 자동 적용에 한 번 넣어 주세요
   ```
4. 연결 코드를 패치 관리자 **[실행] → 자동 적용**의 "연결 코드" 칸에 넣고 저장합니다.

그다음부터는 **[실행] → [자동 적용]** 버튼만 누르면 됩니다. 마리나라가 잠깐 꺼졌다 켜지고, 결과가 화면에 나옵니다.

- 마리나라 업데이트는 평소처럼 런처로 하고, **켤 때만** 도우미로 켜면 됩니다.
- 연결 코드를 잊었으면 `node marinara-patch-helper.mjs --code`로 다시 볼 수 있습니다.

### 2-B. 직접 실행 (도우미 없이)

1. **[실행] → 실행 파일 받기** — 켜 둔 패치가 모두 든 `marinara-patches.mjs`를 받습니다.
2. 마리나라 엔진 폴더에서 터미널을 열고 실행합니다.
   ```bash
   node "C:\Users\나\Downloads\marinara-patches.mjs"
   ```
3. 마리나라를 끕니다(런처 창 닫기 또는 Ctrl+C). 실행 파일이 마리나라가 꺼질 때까지 기다렸다가, 꺼지면 바로 패치합니다. 그러니 2번과 3번은 순서가 바뀌어도 됩니다.
4. "결과: 성공"이 나오면 마리나라를 다시 켭니다. 패치 관리자를 열면 적용 여부가 자동으로 표시됩니다.

옵션: `--restore`(되돌리기) · `--list`(목록만 보기) · `--no-wait`(켜져 있으면 기다리지 않고 그만두기) · 끝에 data 폴더 경로.

### 3. 이미 깔린 패치 찾기

도우미로 마리나라를 켠 뒤 **[검사] → 설치된 패치 찾기 (도우미)**를 누르면, `.env`의 `NODE_OPTIONS`로 불러오는 런타임 패치와 애드온 폴더(예: `gacha-more-money/patch`)의 파일 패치를 모두 찾아 관리자 목록에 넣습니다.

- 런타임 패치는 **켜짐 / 꺼짐 / 버전 다름 / 파일 없음 / 적용 대기**로 나옵니다.
- 카드의 전원 버튼으로 켜고 끄거나, 검사 화면에서 불러오는 순서를 바꾼 뒤 **[재시작해서 적용]**을 누르면 도우미가 `.env`를 고치고 마리나라를 다시 켭니다(이전 `.env`는 `.env.patch-manager-backup`).
- 도우미가 없으면 같은 화면에 나오는 `NODE_OPTIONS=…` 줄을 `.env`에 직접 붙여 넣고 마리나라를 다시 켜면 됩니다.

### 4. 검사 · 백업본 지우기

**[검사] → 이 컴퓨터에서 폴더 고르기**로 엔진 폴더를 고르면, 패치가 남긴 백업본(`server.mjs.gmm-backup` 등)이 나옵니다.

- 크롬·엣지는 화면에서 바로 지웁니다(처음 한 번 폴더 수정 허락을 묻습니다).
- 다른 브라우저는 **정리 파일 받기** → `node marinara-clean-backups.mjs`로 지웁니다.
- 도우미를 쓰고 있다면 **서버에서 검사 (도우미)**를 눌러도 됩니다.

## 🌐 SSH 기준 — 원격 서버 · 호스팅 서버(VPS)에서 돌릴 때

마리나라가 **다른 컴퓨터**(SSH로 접속하는 서버, 따로 산 호스팅 서버)에서 돌아가는 경우입니다. 브라우저에서는 서버 폴더를 열 수 없으므로 **도우미가 꼭 필요합니다.** 설치는 SSH로 한 번만 하면 됩니다.

### 1. 서버에 도우미 설치

```bash
ssh 사용자@서버주소
cd ~/Marinara-Engine          # 마리나라 엔진 폴더 (packages 폴더가 있는 곳)
curl -fsSLO https://raw.githubusercontent.com/lemonpie601/git-patch-manager/main/marinara-patch-helper.mjs
```

`curl`이 없으면 `wget`을 쓰거나, 패치 관리자 **[실행] → 자동 적용**에서 받은 파일을 `scp`·SFTP로 올립니다.

```bash
scp marinara-patch-helper.mjs 사용자@서버주소:~/Marinara-Engine/
```

### 2. 마리나라를 도우미로 켜기

평소 `pnpm start`(또는 `./start.sh`) 대신 이렇게 켭니다. 업데이트·빌드는 평소처럼 하고, **켜는 것만** 도우미로 합니다.

```bash
cd ~/Marinara-Engine
node marinara-patch-helper.mjs
```

SSH 창을 닫아도 계속 돌게 하려면 아래 셋 중 하나를 고릅니다.

**tmux / screen** (가장 간단)

```bash
tmux new -s marinara
node marinara-patch-helper.mjs
# Ctrl+B, D 로 빠져나오기 · 다시 보기: tmux attach -t marinara
```

**systemd 서비스** — 이미 서비스로 돌리고 있다면 `ExecStart`만 바꾸면 됩니다.

```ini
# /etc/systemd/system/marinara.service
[Unit]
Description=Marinara Engine (patch helper)
After=network.target

[Service]
User=사용자
WorkingDirectory=/home/사용자/Marinara-Engine
ExecStart=/usr/bin/node marinara-patch-helper.mjs
Restart=on-failure
KillSignal=SIGINT
TimeoutStopSec=20

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now marinara
journalctl -u marinara -f        # 로그 · 연결 코드 확인
```

**pm2**

```bash
pm2 start marinara-patch-helper.mjs --name marinara --kill-timeout 15000
pm2 logs marinara                # 연결 코드 확인
pm2 save
```

### 3. 연결 코드 넣기

도우미 로그에 나온 연결 코드를 브라우저의 패치 관리자 **[실행] → 자동 적용**에 넣습니다. 로그를 놓쳤으면 서버에서 아래 명령으로 다시 볼 수 있습니다.

```bash
node marinara-patch-helper.mjs --code
```

연결 코드는 **그 브라우저에만** 저장됩니다. 다른 기기에서 쓰려면 그 기기에서도 한 번 넣어 주세요.

### 4. 사용

- **자동 적용** — [실행] → [자동 적용]. 도우미가 마리나라를 정상 재시작하고, 꺼진 틈에 패치를 넣고, 다시 켭니다. 화면이 잠깐 끊겨도 패치는 계속되고, 다시 열면 결과가 보입니다.
- **설치된 패치 찾기** — [검사] → **설치된 패치 찾기 (도우미)**. 서버의 `.env`·애드온 폴더·data 폴더를 도우미가 대신 읽어, 런타임 패치·파일 패치·백업본을 찾아 관리자에 반영합니다. 마리나라는 재시작하지 않습니다.
- **런타임 패치 켜기·끄기·순서** — 바꾼 뒤 **[재시작해서 적용]**. 도우미가 재시작하는 틈에 `.env`의 `NODE_OPTIONS`를 고칩니다.
- **백업본 지우기** — 검사 결과의 [삭제] / [백업본 모두 삭제]. 서버의 도우미가 지웁니다.

### 도우미 없이 하려면

실행 파일을 서버로 올려서 직접 돌립니다. 이때는 마리나라를 직접 꺼야 합니다.

```bash
scp marinara-patches.mjs 사용자@서버주소:~/Marinara-Engine/
ssh 사용자@서버주소
cd ~/Marinara-Engine
node marinara-patches.mjs      # 마리나라가 꺼질 때까지 기다렸다가 패치
# 다른 창에서 마리나라를 끄고(systemctl stop / pm2 stop / Ctrl+C), "결과: 성공"이 나오면 다시 켭니다.
```

### Docker

Docker는 재시작하면 컨테이너째 다시 켜지는 방식이라 도우미를 쓸 수 없습니다. 컨테이너를 멈추고, 같은 data 볼륨을 붙인 일회용 컨테이너에서 실행 파일을 돌려 주세요.

```bash
docker stop marinara
docker run --rm -v marinara-data:/app/data -v "$PWD":/work -w /work node:22 node marinara-patches.mjs /app/data
docker start marinara
```

볼륨 이름(`marinara-data`)과 data 경로(`/app/data`)는 각자 설정에 맞게 바꿔 주세요.

## 보안

- 도우미는 서버에서 Node 코드를 실행할 수 있으므로, **연결 코드로 서명된 작업만** 받습니다.
  - 연결 코드는 서버(`엔진 폴더/.marinara-patch-helper.json`)와 그 코드를 넣은 브라우저에만 있습니다.
  - 마리나라에 접근할 수 있는 다른 사람이 작업을 끼워 넣어도, 서명이 없으면 거절합니다.
- 실행하기 전에 각 패치 코드가 기록된 해시와 같은지 확인합니다. 15분이 넘은 작업과 이미 처리한 작업은 다시 실행하지 않습니다.
- 백업본 정리는 그 순간 도우미가 다시 찾은 백업본 목록에 있는 것만 지웁니다(지금 쓰는 파일은 그 목록에 들어가지 않음).
- 런타임 패치 설정은 엔진 폴더 안에 있는 `.cjs`/`.js`/`.mjs` 파일만 켤 수 있습니다. 엔진 폴더 밖을 가리키는 `--require`는 건드리지 않고 그대로 둡니다.
- 패치를 추가할 때는 코드를 꼭 확인해 주세요. 패치는 서버 파일을 고치는 프로그램입니다.

## 알아 둘 점

- 마리나라는 확장 하나에 **1MB**까지만 저장할 수 있습니다. 패치 코드도 여기에 들어가므로, 넘으면 미리 알려 줍니다.
- 파일 패치는 코드에 남기는 표식(`/*이름:start*/`, `/*이름:head*/`)으로 찾습니다. 표식을 남기지 않는 패치는 "알 수 없음"으로 나옵니다.
- 런타임 패치의 "맞춘 버전"은 코드 속 `gacha-forge-1.8.13`, `Gacha Forge 1.8.13` 같은 글자로 알아냅니다. 이런 패치는 버전이 다르면 대개 조용히 아무것도 하지 않으므로, 패키지를 업데이트한 뒤 "버전 다름"이 뜨면 새 버전용 패치를 받아야 합니다.
- 도우미의 `--discover` 옵션으로 마리나라를 켜지 않고 찾은 결과만 볼 수 있습니다: `node marinara-patch-helper.mjs --discover`
- 대상 패키지(예: 가챠 포지)를 업데이트하면 패치가 사라집니다. 이때 패치 관리자에 **다시 실행 필요**가 뜨므로 한 번 더 적용하면 됩니다.

## 테스트 상태

- 실행 파일, 도우미(자동 적용·검사·백업본 정리·잘못된 서명 거절·재시작 중 틈 무시), 화면은 마리나라의 실제 규칙을 흉내 낸 가짜 서버로 시험했습니다.
- 실제 마리나라 엔진 위에서는 아직 충분히 시험하지 않았습니다. 문제가 있으면 이슈로 알려 주세요.
